# صدور خودکار TLS

رفتار هدف همان چیزی است که در CyberPanel برای SSL خودکار دیده می‌شود: هم نام خود پنل گواهی می‌گیرد، هم هر دامنه‌ای که به سایت‌ها اضافه شود. کلاینت، `acme.sh` است (همان ابزاری که CyberPanel استفاده می‌کند) و اعتبارسنجی HTTP-01 است، نه پلاگین `certbot --nginx`. پلاگین nginx روی `default_server` واحد محسن فایل پیکربندی را تکه‌تکه می‌کرد.

## چه وقت گواهی گرفته می‌شود

- ثبت دامنه پنل از صفحه «گواهی TLS» یا `sudo mohsen` گزینه ۲.
- ساخت سایت با وضعیت فعال، یا فعال کردن بعدی، یا عوض شدن دامنه.
- تایمر `mohsen-tls.timer` هر ۳۰ دقیقه: اگر DNS دیر آماده شده باشد دوباره تلاش می‌کند.
- دکمه «صدور دوباره» روی سایت یا صفحه TLS. این یکی `--force` است و سهمیه هفتگی Let’s Encrypt را مصرف می‌کند.

پیش‌نویس گواهی نمی‌گیرد. دامنه `.local`، `localhost` و آی‌پی گواهی عمومی نمی‌گیرند. ورود اضطراری پنل روی `http://IP:8787/<web-pass>/` می‌ماند.

اگر رکورد `www` به همین سرور برسد و آن نام، سایت یا دامنه پنل جدایی نباشد، در SAN همان گواهی می‌آید. هر دو نام به همان سایت جنگو می‌رسند.

## جریان روی سرور

1. پنل (کاربر `mohsen`) ردیف `Certificate` را «در صف» می‌کند و به سوکت `/run/mohsen/tls.sock` یک خط JSON می‌فرستد.
2. `mohsen-tlsd` با root دستور `manage.py tls_issue` را اجرا می‌کند. gunicorn خودش root نمی‌شود.
3. قبل از تماس با Let’s Encrypt بررسی می‌شود که A/AAAA دامنه یکی از آی‌پی‌های سرور (یا آی‌پی عمومی پشت NAT) باشد، و nginx روی `127.0.0.1:80` فایل چالش را برگرداند.
4. گواهی در `/etc/mohsen/ssl/<دامنه>/` نصب می‌شود. `names.txt` فهرست SAN است.
5. `cert.map` و `key.map` و `redirect.map` از نو نوشته می‌شوند و `nginx -t` بعد از آن reload می‌کند. اگر آزمون nginx خراب باشد، نقشه قبلی برمی‌گردد.
6. از این به بعد HTTP همان نام به HTTPS می‌رود، جز `/.well-known/acme-challenge/`.
7. `acme.sh --cron` حداکثر هر ۱۲ ساعت تمدید را بررسی می‌کند و فایل‌های نصب‌شده را تازه می‌کند. اگر کمتر از ۳۰ روز به انقضا مانده باشد و ۱۲ ساعت از تلاش قبلی گذشته باشد، یک بار دیگر هم صدور بدون `--force` صدا زده می‌شود.

حذف سایت یا حذف دامنه پنل، فایل گواهی و ردیف تمدید را برمی‌دارد. گواهی در Let’s Encrypt revoke نمی‌شود تا سهمیه ابطال هدر نرود.

## فایل‌های سیستم

| مسیر | نقش |
| --- | --- |
| `/root/.acme.sh` | برنامه و حساب ACME |
| `/var/lib/mohsen-acme` | وب‌روت چالش. عمداً بیرون از `/var/lib/mohsen` است چون آن پوشه برای پایگاه داده حالت ۷۵۰ دارد و nginx نمی‌تواند واردش شود |
| `/etc/mohsen/ssl/_default` | گواهی خودامضا برای SNI ناشناس. مرورگر به آن اعتماد نمی‌کند |
| `/etc/mohsen/ssl/*.map` | انتخاب گواهی و فهرست ریدایرکت |
| `/var/log/mohsen/tls.log` | خروجی acme و خطاها |
| `/var/lock/mohsen-tls.lock` | قفل تا دو صدور همزمان قاطی نشوند |

nginx نسخه ۱.۱۸ به بالا لازم است (اوبونتو ۲۲.۰۴ همین را دارد) چون مسیر گواهی متغیر است.

## محیط

در `/etc/mohsen/mohsen.env`:

```text
MOHSEN_ACME_EMAIL=ssl@example.com
MOHSEN_ACME_SERVER=letsencrypt
```

`letsencrypt_test` سرور آزمایشی است و گواهی‌اش در مرورگر اعتماد نمی‌شود. `MOHSEN_HTTPS` را ۱ نکنید: کوکی امن سراسری، ورود HTTP با آی‌پی را می‌شکند. درخواست HTTPS از پشت nginx با `X-Forwarded-Proto` امن شناخته می‌شود.

## اگر صادر نشد

- رکورد A دامنه (و در صورت نیاز www) به آی‌پی همین ماشین باشد. پشت NAT، آی‌پی عمومی از `api.ipify.org` هم قبول است.
- فایروال پورت ۸۰ و ۴۴۳ را باز کند.
- `systemctl status mohsen-tlsd nginx` و `sudo mohsen tls`.
- آخر فایل `/var/log/mohsen/tls.log`.
- سهمیه Let’s Encrypt: ۵ گواهی تکراری در هفته برای یک مجموعه نام. دکمه صدور دوباره را پشت سر هم نزنید.
